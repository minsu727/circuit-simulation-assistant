## Shutdown defect and failed history

The earlier installed 15/45-second tests used forced termination and exited 1.
They were failures. Some normal runs exited in roughly one second, but the old
frozen portable also reproduced the hang (45.028 s, forced, exit 1).

Source diagnostics after FIN→RST captured WinError 10054 in Python 3.13.5
`_ProactorBasePipeTransport._call_connection_lost`. The exception from socket
shutdown skipped close/`server._detach`/completion flag. With Uvicorn connections
and tasks both zero, a closing transport/socket remained in asyncio server
`_clients`; shutdown waited in `Server.wait_closed()` at both 3 and 15 seconds.
Source also timed out at 45.010 s. Signal delivery and process ownership were
correct. The issue is a common runtime defect, independent of installation path
or icon. Selector socket cleanup avoids that failing Proactor path.

Verification now records PID/children/time/exit/fallback and fails after forced
cleanup or nonzero exit. TCP listener and orphan checks supplement health checks.

## Limitations / next steps

Unsigned installer; SmartScreen warnings are possible. Clean VM, Defender,
actual OpenAI API smoke and in-place upgrade of the existing all-users v0.1.0
remain unverified. The Windows Selector policy's socket capacity and lack of
async subprocess/pipe support should be reconsidered if the pinned runtime or
server architecture changes. Current simulator execution is synchronous.

uploaded. Clean-machine validation remains a next step; publication does not
extend the validation evidence above.
